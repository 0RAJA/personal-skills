# 产物版本、冻结与恢复

适用于文档、PPT、HTML、图及生成源，也适用于没有 Git 的材料。版本快照、编辑历史和当前采用关系各有用途。

## 1. 何时冻结

工作稿可持续编辑。以下节点先保全现有版本：

- 用户命名、确认或要求保留版本。
- 已交付、展示或分享过的产物即将被覆盖。
- 阶段产物需要独立评审、比较或回退。

已有内容和哈希匹配的快照可复用，普通探索不逐轮复制。冻结仅保全事实，用户接受、发布与验证结果分别记录。

## 2. 保存什么

按实际依赖保存：交付物、必要本地资源、可编辑源／数据、生成源及运行方法。简短记录版本标识、用途、确认与验证情况、来源／替代关系、文件清单和哈希，以及工作稿和采用入口。

大文件或外部依赖可用可回取位置及指纹引用，说明是否检查过回取；缺失或不可重建的部分列为恢复缺口。生成 HTML 能打开，不代表源和环境足以重建；不复制虚拟环境、凭据或无关数据。

记录可放版本目录 README 或现有清单，不强制机器 schema 或语义化版本号。

## 3. 文件与当前指针

冻结快照保持原字节，修正另建修订。工作稿在原维护位置继续编辑，入口区分采用版与待评审候选；新编号不自动取代已采用版本。

覆盖 current、latest 或无版本文件前，确认其角色及是否已有匹配的保全副本。目标版本已占用且内容不同，换标识或报告冲突；普通进展摘要不视为冻结版本。

## 4. 回退与恢复

优先复制到空目标或独立工作副本，核对清单、哈希和相对资源路径，再按用户要求切换入口。

替换已有工作稿前，核对当前改后哈希、备份原哈希和目标占用。预览后有新修改时保留它，不用旧全文强行覆盖。

分别报告：旧字节匹配、源／依赖齐全、恢复副本可打开、可重建且验证通过；只完成哪项就说明哪项。

## 5. 旧材料与历史缺口

依据真实记录确认版本身份，不凭文件名、日期或“修改前”目录推断曾交付或接受。只剩现存文件时保全它，注明缺失历史；不补造旧快照，也不改写原交付记录。
