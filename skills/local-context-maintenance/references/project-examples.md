# 虚构场景

示例用于理解文档角色和取舍，按已有材料裁剪，不是固定目录、每轮模板或额外记账要求。

## 完整案例：演示材料的跟进与试读

工作稿最初使用“新人先看”页签。给同事试读前保全这一版，随后只在工作稿中将页签改为“阅读顺序”、简介改为“先了解架构，再核对适用范围。”；独立共享包未重新生成。

### 阅读关系

```text
专题 README.md ──当前跟进──→ 已有 progress.md
                              ├─设计依据──→ 方案.md
                              ├─验证依据──→ evidence/静态检查.txt
                              ├─工作稿────→ 演示/index.html
                              └─试读快照──→ 版本/2026-10-30_演示入口_v01.html
```

这是入口的链接关系，不是文件系统目录树。实际记录使用可点击链接；已有 README 可兼任进展，使用 planning-with-files 时沿用它的维护源。

### 四行进展

以下四行写入已有进展；已有详细依据用链接引用，不另建同样的摘要：

```text
当前：演示/index.html 为工作稿，页签“阅读顺序”；采用版尚未确认。
验证：工作稿静态检查 PASS，浏览器 NOT_RUN；依据在 evidence/静态检查.txt。
等待：同事对 2026-10-30_演示入口_v01.html 的试读反馈。
下一步：收到反馈后确定是否改图；需要更新独立共享包时再生成并验证。
```

### 版本对照

| 文件 | 身份与内容 | 分享、采用及验证情况 |
| --- | --- | --- |
| 演示/index.html | 持续编辑的工作稿；页签“阅读顺序”，简介“先了解架构，再核对适用范围。” | 静态 PASS；浏览器 NOT_RUN；采用版未确认 |
| 版本/2026-10-30_演示入口_v01.html | 冻结快照；保留“新人先看”，简介“先了解架构，再阅读验证边界。” | 已试读，未验收；入口副本依赖演示目录内的原资源 |
| 演示/共享.html | 先前生成的独立共享包，本轮未更新 | 原验证属历史，不代表本轮文案已验证 |

试读快照始终保持原文；冻结后改变的是工作稿。这里用文件身份说明先后关系，不用“当时入口”兼指两个版本。

快照名称是可选示例：日期表示冻结日，v01 是同日同产物的快照序号；已有版本号继续沿用，不追溯改名。只有需保全的节点才命名、留副本，编号大小不决定采用关系。

本例快照只保全入口 HTML，恢复到演示/index.html 才能沿用原相对路径；资源指纹保存在已有 progress.md，独立恢复尚未验证。

## 接纳新增材料

说明和样本按依赖成组归入原专题；原始排查样本按证据角色保留。用途不明则原位待核实，不重排全库。

## 当前结论与讨论混杂

旧文写“尚无样本”，后来已采样但未验证。原处改为“已采样、待验证”并保留依据，不写成业务通过，也不只改摘要。

## 恢复时出现后续修改

预演回退后有人追加备注，当前哈希已变：保留新稿，把旧版复制到空目录，说明原路径冲突。
