# 持续维护：阶段详情

按当前问题选读，不要求新建固定目录或记录文件。

## 1. 开始与恢复

先读项目规范、材料入口及相关事项，按别名或主题词定位已有跟进。已知 ignored 目录直接指定路径检索；不遍历全部历史。

有多个进展时，辨别独立事项与历史阶段，选定当前维护源。旧路径失效时追查后续记录，不重放旧迁移清单。

根／分类链接专题；专题链接有效资料与当前进展。入口不在本轮可写范围时，留下待补事项。

## 2. 讨论与探索

只保留影响后续行动的证据、决定及理由、未决差异、已排除路径和排除条件。

事实给来源和时间／环境；候选写清待确认条件。更新结论时在原维护源说明承接关系，保留有取证或恢复价值的历史原文。无法确认哪份有效时标为待核实，不按日期、文件名或相同字节合并／删除。

## 3. 执行与验证

材料随事项归属，方案、排查与验证用链接关联，不复制结论。沿用已有规划记录；新证据改变范围时同步目标、约束与下一步。

保留必要的环境、输入、结果和证据位置。局部检查、独立审阅与业务验收分别报告，历史测试不代表本轮通过。

交接核对本次变化直接关联的活跃结论。旧表述已失效时，原处注明调查时／修复前语境或链接替代结论；原日志、快照、回执保留当时内容。

## 4. 产物更新与阶段交付

有生成源时修改源并重建，说明源与交付物的关系；仅改工作稿时注明共享产物是否尚未更新。覆盖、冻结或恢复按[版本规则](artifact-versions.md)执行。

交付说明只补用户需要的版本入口、确认状态、验证边界与后续动作。根／分类不收录每轮临时日志；专题保留当前事项入口。

## 5. 暂停／结束与跨 Agent 接续

检查文件能否独立恢复停止点。将新等待条件、暂缓决定、未执行的验证及下一动作补到已有进展或单文件说明，不能只写在最终答复里。

已有完整信息则不重写；设计、计划和证据中的细节给链接。交接摘要可包含目标与范围、阶段、关键决定、已尝试路径、阻塞与恢复依赖，按需取用。

## 6. 集中整理、迁移与恢复

围绕实际问题列出受影响路径、依赖、动作和检查方式；移动前核对源／目标并预览。归属冲突、合并或归档会改变有效资料时，说明证据与取舍；不以整理为由扩大删除范围。

1. 改写原件前保存并核对原文备份；哈希不能替代原文。识别软链接真实目标、共享工作区及未提交修改。
2. 临写复核内容哈希与目标占用；前提变化就跳过或重评，不覆盖未知目标。源、样本和依赖成组处理。
3. 修复受影响的入站链接、相对路径和运行位置；只做所需静态检查，不执行历史业务脚本。
4. 留下实际执行／跳过／冲突项、前后哈希、备份与未检查范围。恢复按实际执行项逆序核对，遇后续修改则保留现状并提供独立恢复副本。
