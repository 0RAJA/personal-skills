# 本地上下文维护

让下一位 Agent 找得到资料、接得上进展、回查得了版本。随主任务持续维护，无需用户重复点名。

## 工作方式

- 优先复用已有说明和进展；使用 planning-with-files 时共用其记录。选定本事项的进展文件时，确认能从最近的已有专题／事项入口沿链接找到它；缺链接就同步补齐。
- 只补会影响后续行动的新信息。普通确认、无变化轮次不写记录；答复以主任务结论为主。
- 遵守本轮可写范围；受限时延后补维护，不为整理扩大权限或阻塞主任务。

## 阶段动作

只执行当前阶段需要的动作，不逐轮跑完整清单。

| 阶段 | 动作 |
| --- | --- |
| 开始／恢复 | 从已有专题入口找到当前事项，按需读计划、进展和证据。 |
| 讨论／探索 | 留下决定、理由与未决项，分清事实、假设和候选。 |
| 执行／验证 | 更新原维护源；范围变化同步约束，区分 PASS、FAIL、NOT_RUN、BLOCKED。 |
| 产物更新 | 覆盖已交付、命名或需独立回退的版本前，先保全原版及必要依赖。 |
| 阶段交付 | 指明采用／候选版本、实际验证范围及遗留项。 |
| 暂停／结束 | 就地补上产物无法表达的停止点、等待条件和下一步，即使产物未改。 |
| 集中整理 | 只调整相关材料，保护原件，修复受影响引用并留下恢复依据。 |

## 组织与保护

- 沿用“材料根 → 用途分类 → 专题 → 事项”，小事项可合并层次或只用一份文档。
- 根／分类负责导航，专题指向当前维护源，事项保存进展。同一事实只维护一处。
- 当前结论注明依据和适用范围；已替代判断保留历史语境。同步澄清直接关联的旧结论，避免只改摘要而正文仍矛盾。
- 整理改写原件前备份并核对。临写复核当前内容及目标占用，保留并发修改；冻结快照和原始证据不原地改写。

## 按需展开

- 复杂接续、信息冲突或迁移：读[阶段详情](references/lifecycle.md)对应章节。
- 冻结、依赖或回退：读[版本与恢复](references/artifact-versions.md)。冻结、用户接受与验证通过分别记录。
- 新建事项进展或首次更新已分享产物时，读[完整案例](references/project-examples.md)；后续按需回查。
- 集中整理需要留档：裁剪[维护记录](assets/maintenance-record.md)，合入已有进展。
