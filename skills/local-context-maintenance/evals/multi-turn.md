# 可复用回归评测

本目录只保存用例与虚构、脱敏小材料，按历史失败类型重建，不含真实业务原件或旧运行成绩。运行记录放技能包外；不属于日常技能步骤。

## 格式与覆盖

`evals.json` 沿用 Anthropic skill-creator 的 skill_name、evals、id、prompt、files、expected_output、expectations 字段；参照其[字段示例](https://github.com/anthropics/skills/blob/main/skills/skill-creator/references/schemas.md)。fixture_root、followups、cold_prompt、followups 内可选 writable_paths 是本套多轮扩展，不宣称 Claude runner 自动理解这些字段。

| ID | 专题 | 主要覆盖 |
| --- | --- | --- |
| 1 | 运维检查清单 | 新材料和进展的入口可达；暂停、等待与未验证范围 |
| 2 | 同步排查 | 既有孤立跟进接续；旧当前结论、历史代码修改与本轮只读边界 |
| 3 | 展示材料 | 分享→改稿→暂停→全新接续；版本身份、反馈对象、限写和仅确认轮 |

本套不覆盖客户端自动触发、长上下文、并发回退或完整依赖包独立恢复，不能从这三例推断这些能力。历史结果保留在原运行位置。

这些用例不是版式测试。允许沿用原README、计划或进展，不要求四行格式、固定新目录、命名或特定措辞。

## 准备与执行

使用当前项目的 Python 3.9+ 环境；准备器只需标准库。在技能目录中运行：

```sh
python evals/prepare.py --check
python evals/prepare.py --case 3 --out /tmp/context-regression-case3
```

输出必须是技能包外、尚不存在的新目录。准备器只复制材料和运行时技能，不启动 Agent、不运行示例程序、不访问网络。它保留输入布局，runtime-skill 不含 evals 或人类 README；dispatch.json 含后续任务，归编排者保管，不能整份发给执行者。目录隔离不是系统权限沙箱。复制途中失败可能留下半成品新目录，重试改用新目录，不覆盖原运行。

1. 编排者先冻结技能与输入指纹。执行者只收到 runtime-skill/SKILL.md、workspace、当前一轮原 prompt 和允许范围；不提供 evals.json、期望、评分、其他运行或未来轮次。不允许执行者读取准备目录中的 dispatch.json、原技能包或评审材料。
2. 同一 Agent 完成本用例各业务轮次。后续只逐条发送 followups 的自然请求，不重复技能/案例提醒；遵守当轮 writable_paths，空列表表示所有材料只读。仅凭模型答复不算范围通过，要比较轮末工作区字节。
3. 编排者在第0轮与每轮完成后保存请求、原生答复、普通文件字节/哈希及新增/修改/删除项，全部放 workspace 外。执行者只完成业务，不负责写评测日志。不要在执行者未完成时当作轮末取样。
4. 业务轮次结束后，由全新只读 Agent 接收同一运行时技能、workspace 和 cold_prompt，不提供之前聊天、期望或结论。核对接续前后材料无变化，保留其原生答复。
5. 独立评审者收到用例标准、各轮输入/产出、原始字节和冷接续答复，按三维判定并给 evidence_ref。技能正文/加载路由不改的评测整理可只运行新增覆盖，不重跑所有历史组；纯排版只核对差异与引用。

若比较旧/新版，各用独立工作区和新Agent，同一用例逐轮请求相同；记录任何额外提示或环境差异，不能把单次结果说成稳定性提升。未得到完整工具轨迹或token时标未知，不填0；事后读取自述不等于读取日志。

## 判定与输出

分别记录主任务、上下文、维护负担的 PASS / FAIL / NOT_RUN / BLOCKED，并说明证据。必要时用总体PARTIAL概括混合结果，但保留分项，不将可达性或主任务通过当整体通过。

- 主任务：内容正确、保护范围及实际动作符合请求。代码/证据只读不妨碍说明上一轮已经做过的修改。限写轮允许暂缓补维护，恢复说明权限后再核对当前状态。
- 上下文：从原入口沿真实链接能到当前维护源与必要材料；搜索找到孤立记录不算入口可达。现行状态、历史动作、冻结版和工作稿身份分清；以真实用户轮次确认分享/采用/反馈对象，不凭文件名、日期或最大编号推断。
- 负担：维护围绕业务，不强迫额外审批、固定模板或每轮新记录。文件数量只描述规模，不直接证明耗时或token成本。确认轮全文件不变、限写轮差异在允许集合内可机械核对，状态语义仍需评审。

建议每个运行在包外保存 grading.json，包含 case_id、各维度status、expectation/evidence_ref、冷接续事实和未测边界。原FAIL、评分分歧、NOT_RUN保留；修订后另起运行，不覆盖旧成绩。不要运行历史业务脚本，不把静态检查当浏览器/真实联调或独立包恢复通过。

本目录不归档运行输出、完整工具日志、源码快照、真实数据或评分。首次来源是已有单轮、多轮、入口修复和版本归属案例的失效模式；历史原件继续由本地材料入口维护。
